On the `loonas-webapp-2` worktree (as of LNS-457, 2026-07-17), there is no `.env`/`.env.local` file whatsoever (`find . -maxdepth 1 -name ".env*"` returns nothing — `.gitignore` has `.env*`). This is a DIFFERENT and more severe environment gap than the previously-logged `loonas-webapp` (non-2) clone, where memory said "`.env` DOES contain `CLERK_SECRET_KEY` and `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`" (see [[qa-patterns]] "Clerk Environment Gotcha"). Do not assume that finding carries over to this worktree — always `find . -maxdepth 1 -name ".env*"` fresh at the start of a QA run in this repo, since apparently there are at least two clones with different .env states.

**What happens without any Clerk keys:** `@clerk/nextjs` auto-enters "keyless mode" — it silently auto-provisions temporary dev instance keys and injects a client-side redirect through `/clerk-sync-keyless?returnUrl=...` on first load of any route. This is NOT a 500 (unlike the older "missing CLERK_SECRET_KEY → 500 on every route including /sign-in" pattern from LNS-221). Instead:
- `middleware.ts` uses bare `clerkMiddleware()` (no `.protect()`) — it never blocks/redirects server-side for ANY route.
- The ONLY auth gate is client-side: `(authenticated)/_components/protected-page.tsx`'s `ProtectedPage`, which renders `<></>` while `!isLoaded`, then — critically — renders `children` on the SAME tick `isLoaded` flips true regardless of `isSignedIn`, only firing `router.replace("/sign-in")` in a `useEffect` as a side effect. Children (e.g. `PeriodsLayout`) mount and start their OWN data fetch/redirect race immediately.
- Feature-gated route layouts (e.g. `finance/periods/layout.tsx`, presumably `finance/fixed-costs` too) call `useGetCurrentAccount()`; since `clerk.session` is null (keyless mode ≠ actually signed in — confirmed via `window.Clerk.user`/`.session` both falsy in `page.evaluate`), `ClerkSessionService.retrieve()` throws `NO_VALID_SESSION` **synchronously inside the async fetcher, before `HttpRequest.request()` ever calls `fetch()`** — so `page.route()` network interception CANNOT catch this: there is no network request to intercept. The account fetch fails near-instantly, `account` stays null, and the layout's own effect fires `router.replace("/home")`.
- Net effect: **two `router.replace()` calls race** (`ProtectedPage` → `/sign-in`, the feature-gate layout → `/home`), and whichever fires last wins. Empirically NON-DETERMINISTIC across runs: navigating to `/finance/periods` landed on `/home` twice in a row in one test session, while `/finance/fixed-costs` (same session, moments later) landed on `/sign-in`. Do not read significance into which URL you land on — it's a race artifact, not routing logic worth debugging.
- Setting `NEXT_PUBLIC_BASE_API_URL` to a fake host (e.g. `http://mock.qa.local/v1`) at dev-server boot and mocking `page.route('**/accounts/me', ...)` etc. does NOT help — confirmed via a request-listener that captured ZERO requests to `/accounts/` or `/accounting/` paths; the app never gets far enough to issue them.

**Conclusion — don't repeat this attempt cycle:** In this specific environment state (no `.env`, no real backend, Clerk keyless), route-level network mocking is a dead end for ANY `(authenticated)` route, because the blocking failure is a synchronous client-side session-token check that precedes the network layer entirely — there is nothing to intercept. This is a stronger/different blocker than the ordinary "Clerk env gap → 500" or "feature-gate redirect" patterns already logged; those assumed a working session. Here there is no session-establishment path available at all short of completing Clerk's interactive keyless "claim your keys" email flow (not automatable headlessly).

**How to apply:** At the start of any QA run in a repo/worktree with no `.env`, budget ZERO time on live-browser interactive verification (even with route mocking) for anything under `(authenticated)/`. Go straight to exhaustive source-level verification (as the primary deliverable) and flag ALL browser-smoke acceptance criteria as "not exercisable — no Clerk credentials + no backend in this environment; requires either real dev credentials or a seeded staging pass." This is a repo/worktree environment fact, not a defect in the diff under review.
