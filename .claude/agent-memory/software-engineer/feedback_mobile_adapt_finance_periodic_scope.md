1. **Prefer `flex-wrap` + `gap-N` over a `flex-col → sm:flex-row` toggle for toolbar rows containing 2+ independently-sized controls** (e.g. a month navigator [back-button + picker + fwd-button + conditional "today" button] next to a status chip, or 3 action buttons in a row). A hard breakpoint toggle needs the exact pixel math to be right for every viewport in between; `flex-wrap` self-adapts and — critically — never changes desktop (`lg`+) rendering, since wrap only activates when content doesn't fit (at desktop widths there's always room). Applied in `fixed-costs/_components/month-navigator.tsx` and `fixed-costs/page.tsx`'s two toolbar-row divs (nav+chip, and copy/save/close buttons) — the naive per-row math (back 44px + picker min-w-160px + fwd 44px + gaps ≈ 272-384px, plus a status chip, in a ~288-328px content width at 320-360px viewport) provably overflows without this.

2. **`TabFilter` (core, no built-in overflow handling) needs the established `-mx-4 overflow-x-auto px-4 sm:mx-0 sm:overflow-visible sm:px-0` wrapper even for as few as 3 short tabs** — but only if the parent flex container uses `items-start` (shrink-to-fit) rather than default `align-items: stretch`. The existing precedent (`incoming-invoice-table-impl.tsx`) relies on the parent's *default* stretch behavior to make the wrapper full-width automatically; a parent with an explicit `items-start` (like `periods-list.tsx`'s outer `flex flex-col items-start gap-y-4`) breaks that implicit trick, so the wrapper also needs an explicit `w-full sm:w-auto` or it just renders at shrink-to-fit content width and silently overflows the viewport instead of scrolling. Check the parent's `align-items` before copying the reference pattern verbatim.

3. **Extends `feedback_mobile_actionmenu_rows_and_sectioncard_header`'s action-only-row guidance**: that memory covers rows with a status/type badge + `ActionMenu` (2 controls → `trailingTop`/`trailingBottom`). A row with **3+ independent interactive/display controls** (e.g. `period-row.tsx`: label + status chip + an expand/collapse toggle button for an inline allocation panel + `ActionMenu`) doesn't fit `MobileListCard`'s 2-slot model even though `ActionMenu` nesting itself is safe. Built a bespoke `hidden lg:block` / `lg:hidden` dual block instead, hand-mirroring `MobileListCard`'s visual chrome (`px-4 py-3.5` padding, `border-b`, text sizing) rather than force-fitting a 3rd control into `trailingTop`/`trailingBottom`. Still a single component, single file — just not a literal `<MobileListCard>` call. Judge the control count before defaulting to the primitive.

4. **`{label} + <Link font-mono>{uuid}</Link> + {meta}` reference rows (e.g. `year-end-journal-reference.tsx` showing a closing-journal id) are a recurring overflow risk** — a full UUID in `font-mono text-sm` alone is ~250-290px, already tight against a ~280-320px mobile content width before adding the label and date. Fix: `flex-wrap` on the container (not `flex` alone), `min-w-0 max-w-full` + a `truncate` inner `<span>` around just the id text (keep the icon `shrink-0` outside the truncating span), and change a bare `ml-auto` on the trailing meta to `sm:ml-auto` so it only right-aligns once there's room — otherwise on wrap it isolates awkwardly on its own line.

5. **Some pages in this app were already mobile-aware before this epic** — `pph-final-form-card.tsx` and its skeleton already used `grid grid-cols-2 gap-4 max-sm:grid-cols-1`, and `finance/opening-balance`'s `wizard-balances-step.tsx` / `balance-account-input-row.tsx` already had the sticky-footer and `flex-col sm:flex-row` idioms in place, and the wizard has no fixed-width stepper rail at all (contrary to what a generic "wizards have a rail" assumption would predict). Always verify current file state before assuming a documented anti-pattern still applies — several files in this scope needed zero changes.

**Why:** mobile-adapt pass on `finance/fixed-costs`, `finance/periods`, `finance/pph-final`, `finance/opening-balance` (parallel multi-agent mobile-adaptation effort, 2026-07-14).

**How to apply:** When adapting a toolbar row with multiple small controls, default to `flex-wrap` unless there's a strong reason to force a hard stack. When wrapping `TabFilter` (or any core primitive lacking overflow handling) in the standard bleed-scroll wrapper, check the parent's `align-items` first. When a row has more independent controls than `MobileListCard` has slots, build a bespoke dual-block mirroring its chrome rather than compromising the primitive's slot semantics. Treat any `font-mono` id/UUID display as an overflow candidate by default.
