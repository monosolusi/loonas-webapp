When mobile-adapting a desktop-first page (see shared reference doc pattern used across LNS mobile-adapt epic), two kinds of "wide grid" need different fixes:

1. **Browse-list rows** (one row = one entity, whole row is a nav target) → convert to `MobileListCard` (`src/core/presentations/components/table/mobile-list-card.tsx`), keep desktop grid behind `hidden lg:block`/`lg:grid`, put mobile card in a sibling `lg:hidden` div. `MobileListCard` has NO image/avatar slot and only one `meta` line — drop a secondary field (e.g. exact stock qty when a low-stock dot already signals it) rather than trying to cram everything in.

2. **Dense multi-column form-input grids that are NOT a data table** (variant/pricing editor rows, recipe ingredient rows, purchase line-item rows — `grid-cols-[…]` rows containing `TextInput`/`CurrencyInput`/`NumberInput`/combobox cells) → do NOT reuse `TableContainer scrollable` (that component bakes in loading/empty/error chrome + a `rounded-xl border` meant for read-only data tables, wrong fit inside a `SectionCard` form body). Instead wrap directly: `<div className="overflow-x-auto"><div className="min-w-[Npx]">{header grid}{rows}</div></div>`, keeping any non-column-aligned footer (e.g. "+ Tambah Item" button) OUTSIDE the scroll wrapper. Pick `min-w` generously (500–680px depending on column count) so inputs never get squished below a usable width — a squished `CurrencyInput`/combobox is worse than a horizontal scroll.

3. **Dense read-only data tables nested inside a `SectionCard`** (stock table, stock-movement history, production/purchase item history — `-mx-6 -mb-6` bleed pattern with a `grid-cols-[…]` header + matching row grids) → wrap the whole `-mx-6 -mb-6` block in `overflow-x-auto` and put `min-w-[560px]` (or similar) on an inner div containing BOTH the header row and the data rows, so they scroll together. If the row-rendering component lives in an out-of-scope feature dir (e.g. `features/inventory/presentations/components/stock-movement-table.tsx` when your scope is `products/**`), you can still fix this from the in-scope parent file — just confirm the out-of-scope row component's `grid-cols-[…]` matches the header's, then wrap both without editing the out-of-scope file.

4. **Dense `TableContainer`-wrapped matrix where the brief says "leave the structural choice as-is"** (e.g. profitability product×variant table driven by a `grid-template-columns: var(--…)` CSS var) — some pages already hand-roll `<TableContainer><div className="overflow-x-auto"><TableHeader .../><rows/></div></TableContainer>` WITHOUT the `scrollable` prop (TableContainer used only for loading/error/empty chrome). Here each row is its OWN independent `display:grid` div (not a shared grid), so header and rows can in principle overflow to slightly different widths. Fix: add one `min-w-[Npx]` div INSIDE the `overflow-x-auto`, wrapping the header AND the rows-container together, so they share one width reference — same shape as `ledger-detail-impl.tsx`'s `overflow-x-auto > min-w-[640px] > {header}{rows}`, just nested one level deeper inside `TableContainer`. Compute `min-w` from the CSS var's own track minimums (e.g. `--grid-profitability-cols: minmax(280px,2fr) 200px 160px 200px 100px` → 280+200+160+200+100 = 940 → `min-w-[940px]`) rather than guessing a round number — fixed-px tracks and a `minmax(Npx, …)` track's floor are both real per-column minimums that must sum into the wrapper. `TablePagination` stays a sibling OUTSIDE the `overflow-x-auto` div (unchanged, inside `TableContainer`).

**Why:** LNS mobile-adapt epic (products/productions/purchasing scope) — `VariantTable`, `RecipeFormDialog`'s ingredient grid, and `PurchaseCreateFormCard`'s item grid all had 3-5 columns of real inputs (not just text) that would be unusable squished to fit 320-360px; `ProductDetailStockCard`/`ProductDetailMovementCard`/`ProductionDetailItemsCard`/`PurchaseDetailItemsCard` all had the `-mx-6 -mb-6` dense-table-in-card bleed pattern. Case 4: finance/profitability scope — `profitability-table.tsx` already had a manual `overflow-x-auto` (correct per brief) but no explicit `min-w`, relying only on the CSS var's implicit grid-track minimums.

**How to apply:** When a brief says "wide matrices → horizontal-scroll strategy" and shows `TableContainer scrollable` as the example, check whether the wide content is an actual `TableContainer`-wrapped browse/data table (use `TableContainer scrollable`) or an ad-hoc `grid-cols-[…]` block inside a `SectionCard` (use the raw `overflow-x-auto` + `min-w` wrapper instead — cleaner, no unwanted chrome).

Related: page-header title+button rows use `flex flex-col gap-4 sm:flex-row sm:items-center sm:justify-between` with the button/Link both getting `w-full sm:w-auto` (established in `src/app/(authenticated)/invoices/_components/invoice-list-page-shell.tsx` — reuse this exact idiom for other list headers with an action button).

Two-column detail/create page bodies (`flex flex-row gap-x-6` sidebar layout, or `grid grid-cols-2`) → `flex flex-col gap-6 lg:flex-row lg:gap-x-6` (sidebar column becomes `lg:w-[280px] lg:shrink-0`, sticky becomes `lg:sticky lg:top-8`) or `grid grid-cols-1 gap-6 sm:grid-cols-2 sm:gap-x-6`. Remember to also fix the matching `*-skeleton.tsx`/`*-loading.tsx` placeholder — it mirrors the real layout and is easy to miss.
