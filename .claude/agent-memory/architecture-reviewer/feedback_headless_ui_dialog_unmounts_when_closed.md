name: headless-ui-dialog-unmounts-when-closed
description: A closed LoonasDialog IS unmounted from the DOM — the InternalDialog unmount=false default never applies because the wrapping Transition defaults unmount=true; verified against installed @headlessui/react 2.2.9
metadata:
  type: feedback
---

When reviewing any claim about what a closed `LoonasDialog` / Headless UI `Dialog` leaves in the DOM, do **not** accept "`unmount` defaults to `false`, so it stays mounted as `display:none`". That reads the wrong default. Verify the chain, not the one line.

**Why:** verified in the installed `@headlessui/react` 2.2.9 (`node_modules/@headlessui/react/dist/components/dialog/dialog.js` and `.../transition/transition.js`). `DialogFn` renders `<Transition show={open} transition={transition} unmount={rest.unmount}><InternalDialog/></Transition>`. `LoonasDialog` never forwards an `unmount` prop, so `rest.unmount === undefined`; `TransitionRoot` destructures `let {show, appear=false, unmount:S=!0, ...}` and `undefined` triggers the **`true`** default. It then renders with `features = RenderStrategy|Static` and `ourProps: {unmount: S}` → `RenderStrategy.Unmount` → returns `null`. `InternalDialog`'s own `unmount = false` default never gets a chance to apply, because the outer Transition already removed the subtree. Context7 (`/tailwindlabs/headlessui/_headlessui_react_v2_2_9`) quotes both defaults and it is easy to cite only the InternalDialog one and reach the opposite conclusion — a sibling agent did exactly that and wrote it into its own durable memory (LNS negative-stock guard, 2026-08-11).

**How to apply:** two consequences for review. (1) Worries about an *always-mounted* closed dialog — duplicate focus traps, a permanently-live `role="alert"` region, stale DOM form state — are moot; there is no DOM subtree while closed. (2) The mutually-exclusive-sibling-dialogs shape (`<><Blocked open={cond}/><Form open={!cond}/></>`) is still the right call, but for a different reason than usually stated: the Transition plays the leave animation on nested `TransitionChild`s (backdrop/panel carry `transition`) and unmounts only after, whereas an early return tears the `<Dialog>` down synchronously and the leave never plays. Approve the shape, correct the rationale. Related: [[css-hidden-dual-branch-singleton]] is the opposite case — CSS `hidden` really does keep both branches mounted.
